# 函数图（CFG）绘制原理

> 对应代码：`ui/function_graph.cpp` / `ui/function_graph.h`
> 效果：对标 Ghidra Function Graph 的精简实现——函数控制流图，
> 块自上而下分层布局、正交折线连边、回边走左侧通道，
> 支持缩放/平移/选中/双击跳转反汇编。

---

## 0. 总体管线

从"一个地址"到"屏幕上的图"，经过六步，每步的输出是下一步的输入：

```
入口地址
  │ ① CFG 构建      function_graph_builder::build()
  ▼                 递归下降 + 基本块切分 → blocks[] + edges[]
fg_function
  │ ② 块测量        measure_blocks()      用当前字体量每个块的像素宽高
  │ ③ 分层+排序     assign_grid()         回边标记 → 分层 → 行序 → 降交叉
  │ ④ 坐标定位      position_blocks()     行列主轴聚合 → 世界坐标 (x,y,w,h)
  │ ⑤ 边路由        route_edges()         正交折线 + 锚点错开 + 回边通道
  ▼
render()            世界坐标 → 屏幕坐标（缩放/平移），ImDrawList 绘制
```

这个 ③④⑤ 的组合就是经典的 **Sugiyama 层次布局框架**（分层 → 交叉最小化 →
坐标分配）的简化版，与 Ghidra 的 flowchart 布局同一思路。

核心数据结构：

```cpp
struct fg_block {
    uint64_t start = 0, end = 0;       // 块的地址区间 [start, end)
    std::vector<disasm_line> insns;
    bool filled = false;               // 已完成顺序解码

    int  edge_fall = -1;  ...          // 三类出边（fall/taken/jmp），-1 = 无
    int  col = 0, row = 0;             // 布局结果：层号 + 层内序号
    float x = 0, y = 0, w = 0, h = 0;  // 布局结果：世界坐标
    bool is_entry = false, is_ret = false, truncated = false;
};

struct fg_edge {
    int from = -1, to = -1;            // 块索引
    fg_edge_kind kind;                 // fall（红）/ taken（蓝）/ uncond（紫）
    bool back = false;                 // 回边（DFS 判定），路由绕左侧
    std::vector<ImVec2> pts;           // 世界坐标折线（末点 = 箭头位置）
};
```

## 1. 第一步：CFG 构建（递归下降 + 基本块切分）

### 1.1 函数头识别——`find_function_entry()`

用户往往从**函数中部某条指令**（比如右键 `setnz cl`）打开函数图，
必须先回溯到真正的函数入口。按可靠性从高到低五级启发：

| 级 | 判据 | 依据 |
|---|---|---|
| 1 | 地址恰好命中导出符号 | 导出符号 = 函数起点 |
| 2 | 紧前方 ≥2 字节 `CC`(int3)/`90`(nop) 填充 | 编译器在函数间填 padding |
| 3 | **向后边界回溯 + 线性解码验证**（核心，下述） | CE/Ghidra 共同思路 |
| 4 | ≤0x1000 内最近导出符号且线性能解码到达 | 兜底加强 |
| 5 | 地址本身 | CE 无信息时的行为 |

**第 3 级是关键**。原理：编译器生成的函数之间必有 `ret(C3)` / `int3(CC)` /
`nop(90)` 之类的边界字节。算法分两步：

**步骤 A —— 收集边界候选**：在目标地址前最多 0x400 字节的内存里，
找出所有"终止字节之后"的位置：

```cpp
while (i + 1 < buf.size()) {
    const uint8_t b = buf[i];
    if (b == 0xCC || b == 0x90) {
        while (i < buf.size() && (buf[i] == 0xCC || buf[i] == 0x90))
            ++i;                               // 跳过整个填充串
        if (i < buf.size())
            cands.push_back(addr - back + i);  // 填充串之后是候选函数头
    } else if (b == 0xC3) {
        cands.push_back(addr - back + i + 1);  // ret 之后也是候选
        ++i;
    } else {
        ++i;
    }
}
```

**步骤 B —— 线性解码验证**：按地址从早到晚逐个验证候选。真正的函数头
满足：从它开始**顺序解码**（跳转/call 只计长度、不跟随，不跨越
ret/int3），指令边界**恰好落在**目标地址上。函数中部的错误起点会错位，
几乎不可能精确落上：

```cpp
static bool linear_reaches(disassembler& d, uint64_t cand, uint64_t target)
{
    if (cand == 0 || cand >= target || target - cand > 0x1000)
        return false;
    const auto lines = d.disassemble(cand, 512);
    uint64_t cur = cand;
    for (const auto& ln : lines) {
        if (ln.address != cur)
            return false;                        // 解码失败/错位
        if (ln.is_ret || ln.bytes.compare(0, 2, "CC") == 0)
            return false;                        // 不跨越 ret/int3（不串到别的函数）
        cur += ln.length;
        if (cur == target) return true;          // 恰好命中 → 验证通过
        if (cur > target)  return false;
    }
    return false;
}
```

"不跨越 ret/int3"保证不会把上一个函数的开头误判为当前函数的头；
"恰好落在 target"利用了指令边界对齐的自证性。最早通过验证的边界即函数头。

### 1.2 工作队列式递归下降

找到入口后，从入口开始构造 CFG。采用**工作队列**（而非递归）实现
递归下降，防止深函数爆栈：

```cpp
ensure_block(entry);
out.blocks[0].is_entry = true;

for (size_t qi = 0; qi < queue_.size() && !out.truncated; ++qi) {
    const uint64_t start = queue_[qi];
    const int bi = block_of_[start];
    if (f_->blocks[bi].filled) continue;
    f_->blocks[bi].filled = true;

    uint64_t cur = start;
    for (;;) {                       // 顺序解码直到块终结
        disasm_line ln;
        if (!decode_next(cur, ln)) { truncated = true; break; }  // 不可读
        f_->blocks[bi].insns.push_back(ln);
        cur += ln.length;

        if (ln.is_ret) break;                              // ret 终止块

        if (call) continue;                                // call 不影响顺序流

        if (无条件 jmp)  { 连 jmp 边; break; }             // jmp 终止块
        if (条件 jcc)    { 连 taken 边; 连 fall 边到新块; break; }  // jcc 终止块

        // 顺序后继撞上已有块：连 fall 边收敛（不重复解码）
        ...
    }
}
```

**基本块语义**（标准编译器定义，与 Ghidra 一致）——块只在三种地方结束：

1. `ret`：无后继；
2. 无条件 `jmp`：一个后继（目标出 ±0x8000 窗口则标记 `jmp_external`，只显示不连边）；
3. 条件 `jcc`：**两个后继**——taken 目标成新块，fall-through 也另起新块，
   分别连 `taken` 边和 `fall` 边。跳转指令因此永远不会出现在块中部。

`decode_next` 带一个顺序解码缓存（一次 `ReadProcessMemory` 读 512 字节、
解码 64 条，之后顺序消费），把块级解码的系统调用开销降到最低：

```cpp
bool function_graph_builder::decode_next(uint64_t addr, disasm_line& out)
{
    // 顺序命中缓存则直接消费
    if (!cache_.empty() && addr == cache_next_ && cache_idx_ < cache_.size()) {
        out = cache_[cache_idx_++];
        cache_next_ += out.length;
        return true;
    }
    cache_ = dis_.disassemble(addr, 64);   // miss：重新批量解码
    ...
}
```

### 1.3 块重叠消解：`resolve_target` / `split_block`

递归下降时，一个跳转目标可能落在**已解码块的中间**。为保证块互不重叠
（基本块定义要求），把宿主块从目标地址处一分为二：

```cpp
int function_graph_builder::resolve_target(uint64_t target)
{
    const auto it = block_of_.find(target);
    if (it != block_of_.end())
        return it->second;                  // 恰好是某块起点：直接返回
    const int owner = find_block_containing(target);
    if (owner >= 0) {
        split_block(owner, target);         // 落在块中部：切开
        return block_of_[target];
    }
    return ensure_block(target);            // 全新地址：建 shell 入队
}
```

```cpp
void function_graph_builder::split_block(int bi, uint64_t at)
{
    // 后半：继承原块的全部出边和 [at, end) 的指令
    // 前半：保留原 start（承接所有指向原起点的边），清空出边，
    //       加一条 fall 边指向后半
}
```

拆分方向的选择有讲究：**前半保留原 start**——因为其它地方可能已经连了
"→ 原 start"的边，保留起点让这些边继续有效；后半接走出边；前后半之间
补一条 fall 边维持语义。

### 1.4 防御性上限

```cpp
constexpr int kMaxInsn   = 8000;    // 指令总数上限
constexpr int kMaxBlocks = 1200;    // 块数上限
constexpr uint64_t kRange = 0x8000; // 跳转目标视为"函数内"的地址窗口
```

超限置 `truncated`，界面显示"(已截断)"——防止把数据段当代码导致 UI 卡死。

## 2. 第二步：块测量

布局前需要知道每个块的像素尺寸。用当前 ImGui 字体逐行量文本宽度，
取最大值加内边距（标题 = 就近符号标签，无符号回退十六进制地址）：

```cpp
static void measure_blocks(fg_function& g)
{
    const float line_h  = ImGui::GetTextLineHeight();
    const float title_h = line_h + kTitlePadY * 2.f;
    for (auto& b : g.blocks) {
        float w = ImGui::CalcTextSize(block_title(b, g).c_str()).x;
        for (const auto& in : b.insns)
            w = std::max(w, ImGui::CalcTextSize(in.text.c_str()).x);
        b.w = std::max(w + kPadX * 2.f + 4.f, 70.f);   // 最小宽 70
        b.h = title_h + (float)b.insns.size() * line_h + kPadY * 2.f;
    }
}
```

**测量与渲染必须用同一段文本**（`block_title`），否则标题会溢出块边框。

## 3. 第三步：分层与排序（Sugiyama 简化版）

`assign_grid()` 是布局的灵魂，分四步。

### 3.1 回边标记——DFS 三色法

"回边"（back edge）= 指向 DFS 栈内节点（灰色）的边，即循环的"往回跳"。
标准 **DFS 三色着色**：白(0)=未访问、灰(1)=在当前 DFS 栈、黑(2)=已完成：

```cpp
std::vector<uint8_t> color(n, 0);
// 迭代式 DFS（显式栈，防深图爆栈）
while (!st.empty()) {
    const int u = st.back().first;
    if (st.back().second < adj[u].size()) {
        const int ei = adj[u][st.back().second++];
        const int v = g.edges[ei].to;
        if (color[v] == 1)      g.edges[ei].back = true;  // 指向栈内 → 回边！
        else if (color[v] == 0) { color[v] = 1; st.push_back({v, 0}); }
    } else {
        color[u] = 2;                                     // 完成
        st.pop_back();
    }
}
```

回边在后续分层中被"豁免"（不参与层号推进），在路由中走左侧专用通道。

### 3.2 最长路径分层

目标：任何前向边都"向下"指（`col[to] > col[from]`），且每个节点落在
尽可能深的层——这样图的主流向自上而下，分支自然铺开。用**最长路径法**
迭代到不动点（图中无环保障收敛，因为回边已被排除）：

```cpp
std::vector<int> col(n, 0);
for (int pass = 0; pass < n; ++pass) {        // 最多 n 轮
    bool changed = false;
    for (const auto& e : g.edges) {
        if (e.back) continue;                 // 回边不参与
        if (col[e.to] < col[e.from] + 1) {
            col[e.to] = col[e.from] + 1;      // 目标至少在源下一层
            changed = true;
        }
    }
    if (!changed) break;                      // 不动点：层号稳定
}
```

这是 Bellman-Ford 式的松弛：每轮把每条边的 `col[to]` 推到
`col[from]+1`，直到没有任何更新。收敛后 `col[i]` 即块 i 的层号。

### 3.3 行序初始化——DFS 前序

同一层内多个块需要左右排列的初始顺序。用 DFS 前序（出边按
fall→taken→jmp 排序，让主 flow 靠左），同层计数器依次分配行号：

```cpp
std::vector<int> col_cnt(maxc + 1, 0);
std::vector<int> stk{0};                      // 从入口块（0 号）出发
while (!stk.empty()) {
    const int u = stk.back(); stk.pop_back();
    if (row[u] >= 0) continue;
    row[u] = col_cnt[col[u]]++;               // 同层按访问次序排
    for (int ei : adj[u])
        if (row[g.edges[ei].to] < 0)
            stk.push_back(g.edges[ei].to);
}
```

### 3.4 降交叉——重心法（Barycenter Heuristic）

初始序在同一层有多个分支目标时会大量交叉。**重心法**是 Sugiyama 框架
标准第 2 步：对每层每个块，算它所有邻居（上层+下层）行号的平均：

```cpp
for (int pass = 0; pass < 4; ++pass) {           // 4 轮交替扫描
    const bool fwd = (pass % 2) == 0;            // 偶数轮自上而下，奇数轮反向
    for (每层 c) {
        for (int u : by_col[c]) {
            float sum = 0; int cnt = 0;
            for (int v : succ[u]) { sum += row[v]; ++cnt; }
            for (int v : pred[u]) { sum += row[v]; ++cnt; }
            key[u] = cnt ? sum / cnt : row[u];   // 重心 = 邻居行号均值
        }
        按 key 稳定排序 → 重排该层行号
    }
}
```

原理：把每个块移动到它邻居的"重心"位置，能让跨越的边数局部最少。
交替向上/向下扫描 4 轮是精度与耗时的折中（精确最小化交叉是 NP-hard）。

### 3.5 坐标定位

`position_blocks()` 把 (col, row) 换算成世界坐标——**行列主轴聚合**：
每列高度取列内最高块，每行宽度取行内最宽块，然后顺序累加：

```cpp
for (const auto& b : g.blocks) {
    col_h[b.col] = std::max(col_h[b.col], b.h);   // 列高 = 最高块
    row_w[b.row] = std::max(row_w[b.row], b.w);   // 行宽 = 最宽块
}
float y = 0;
for (int c = 0; c <= maxc; ++c) { col_y[c] = y; y += col_h[c] + kColGap; }
float x = 0;
for (int r = 0; r <= maxr; ++r) { row_x[r] = x; x += row_w[r] + kRowGap; }
// 每块在所属行/列槽内居中
b.x = row_x[b.row] + (row_w[b.row] - b.w) * 0.5f;
b.y = col_y[b.col]  + (col_h[b.col] - b.h) * 0.5f;
```

效果：同一层的块顶部对齐（像 Ghidra），同层块之间留 `kRowGap=56px`
水平间距，层与层之间留 `kColGap=84px` 垂直走廊——这条走廊正是第 4 步
边路由画水平段的地方。

## 4. 第四步：边路由（正交折线）

`route_edges()` 为每条边生成折线顶点 `pts`，分四种情形。

### 4.1 前向边：底部出、顶部入 + 水平走廊

```cpp
// 出/入锚点在同块的多条边之间错开，避免重叠
const int oi = out_i[e.from]++;
float sx = u.x + u.w * 0.5f
         + ((float)oi - (float)(out_cnt[e.from] - 1) * 0.5f) * kAnchorStep;
sx = std::clamp(sx, u.x + 6.f, u.x + u.w - 6.f);
// 目标块顶部入点 dx 同理 ...

// 水平走廊：放在源块底与目标块顶的层间隙里，
// 同一 (源列,目标列) 的多条边按 lane 序号依次下移，互不压线
const int ln = lane[{u.col, v.col}]++;
const float lo = u.y + u.h + 8.f;
const float hi = std::max(lo + 1.f, v.y - 8.f);
const float ymid = std::min(lo + kLaneH * (float)ln, hi);
e.pts = { {sx, u.y + u.h}, {sx, ymid}, {dx, ymid}, {dx, v.y} };
```

折线为"底部中点出 → 垂直下到走廊 → 水平平移 → 垂直下到目标顶"，
四个点构成标准正交连线。走廊用 `std::map<pair<列,列>, int>` 分配
lane 序号，层间距 `kColGap` 内可容纳多条平行线（每条占 `kLaneH=11px`）。

### 4.2 回边：左侧专用通道

回边（循环往回跳）走图外左侧，按目标列分配纵向通道：

```cpp
const int ln = lane[{std::min(u.col, v.col), -1}]++;
const float xl = std::min(u.x, v.x) - 24.f - kLaneW * (float)ln;  // 越早的目标越靠左
e.pts = { {u.x, sy}, {xl, sy}, {xl, dy}, {v.x, dy} };   // 左出 → 纵向 → 右入
```

### 4.3 自环：右侧小回环

`jmp` 到自己（自旋等待）画一个右侧矩形小环：

```cpp
if (e.from == e.to) {
    e.pts = { {r, cy}, {r + 16.f, cy}, {r + 16.f, u.y - 10.f},
              {u.x + u.w * 0.5f, u.y - 10.f}, {u.x + u.w * 0.5f, u.y} };
}
```

## 5. 第五步：渲染与交互

### 5.1 世界坐标 → 屏幕坐标

画布是一个 child 窗口，图存于"世界坐标系"，渲染时线性映射：

```cpp
const auto w2s = [&](const ImVec2& w) {
    return ImVec2(p0.x + (w.x - scroll_.x) * zoom_,
                  p0.y + (w.y - scroll_.y) * zoom_);
};
```

配合 `view_min/view_max`（当前视口在世界系下的范围 ±60px 余量）做
**视口剔除**——屏幕外的块和边直接跳过，大图也流畅。

### 5.2 滚轮缩放（鼠标锚点）

缩放时保持鼠标指着的**世界坐标点**不动。设鼠标屏幕位置 `m`、缩放前
`old`、缩放后 `zoom`，世界点 `k = (m - p0) / old`，缩放后它在屏幕上的
新位置是 `(m - p0) / zoom + scroll_new`，令其等于 `m` 解出滚动修正：

```cpp
const float old = zoom_;
zoom_ = std::clamp(zoom_ * (wheel > 0 ? 1.15f : 1/1.15f), 0.08f, 4.0f);
const float kx = (mp.x - p0.x) / old, ky = (mp.y - p0.y) / old;
scroll_.x += kx - (mp.x - p0.x) / zoom_;
scroll_.y += ky - (mp.y - p0.y) / zoom_;
```

这是所有画布类软件（地图/编辑器）的标准"锚点缩放"公式。

### 5.3 绘制顺序与细节

```
1. 所有边（AddPolyline 折线 + 收集箭头三角）
2. 所有块（背景 → 标题条 → 边框 → 文本）
3. 所有箭头三角（最后补画，避免被块背景遮住尖端）
```

块的标题条按语义着色：**入口绿、ret 结尾红、普通灰**；指令文本里
跳转目标已替换为 `<模块.符号+偏移>` 标签（`decorate_block_insns`）。
低缩放分级降载：`zoom < 0.35` 只画块框，`< 0.75` 不画指令文本。

### 5.4 交互

| 操作 | 实现 |
|---|---|
| 单击选中 | `hit_block()`：屏幕坐标 → 世界坐标，逆序遍历块做 AABB 测试 |
| 拖拽平移 | `IsMouseDown` 期间 `scroll -= Δmouse / zoom` |
| 滚轮缩放 | 上述锚点公式 |
| 双击块 | 跳转反汇编视图到块起始地址 |
| 适应窗口 | `fit_view()`：图包围盒与画布求最小缩放比 ×0.92，居中 |

## 6. 与 Ghidra / CE 的对应关系

| 功能 | Ghidra | 本实现 |
|---|---|---|
| 基本块切分 | CodeBlock 模型（跳转终止块） | 相同语义，工作队列递归下降 |
| 函数入口 | 分析器（call 目标 + 模式匹配） | 符号/padding/边界回溯+线性验证 |
| 分层布局 | Sugiyama 层次布局 | 最长路径分层（迭代松弛） |
| 交叉最小化 | 边重心排序 | 重心法 4 轮交替扫描 |
| 回边处理 | 环边检测，路由避开 | DFS 三色标记，走左侧通道 |
| 边路由 | 正交折线 + 通道分配 | 锚点错开 + lane 走廊 |

## 7. 小结（算法清单）

| 环节 | 算法 | 复杂度 |
|---|---|---|
| 函数头识别 | 边界收集 + 线性解码验证 | O(候选数 × 解码长度) |
| CFG 构建 | 工作队列递归下降 + 块拆分 | O(指令数 × 块查找) |
| 回边标记 | DFS 三色着色 | O(V + E) |
| 分层 | 最长路径迭代松弛 | O(V·E) 上界 |
| 行序 | DFS 前序 | O(V + E) |
| 降交叉 | 重心法 4 轮 | O(4·E) |
| 定位 | 行列主轴聚合 | O(V) |
| 边路由 | 锚点错开 + lane 分配 | O(E log E)（map） |
