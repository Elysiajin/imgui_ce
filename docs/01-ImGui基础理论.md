# 第一章 · ImGui 基础理论

> 目标：建立正确的心智模型。读完这章，你要能回答三个问题——ImGui 由哪些部分组成？它是怎么把画面画出来的？它和 Qt/MFC 到底差在哪？

---

## 1.1 一句话认识 Dear ImGui

Dear ImGui 是一个 **bloat-free（无冗余）的即时模式 GUI（Immediate Mode GUI）库**，主要为游戏和工具类软件提供调试界面、编辑器、内部工具。它是**纯 C++ 库，不依赖任何外部图形 API**，通过"后端（backend）"接入你现有的渲染环境（DirectX、OpenGL、Vulkan、Metal、甚至软件渲染）。

它由 Omar Cornut 创建，开源（MIT 协议），在游戏和图形行业里几乎成了"调试 UI 的事实标准"。

我们项目用的版本是 **1.92.5 WIP（docking 分支）**——这个分支额外提供了窗口停靠（Docking）、多视口（Multi-Viewport）等能力，是很多编辑器类软件（包括我们即将写的文本编辑器）的基础。

---

## 1.2 核心构成组件及其分工

打开 `libs/Imgui/`，你会看到一堆文件。它们不是随便堆在一起的，而是严格分层、职责分明。先看一张"全景图"：

```
┌─────────────────────────────────────────────────────┐
│              你的应用程序（Application）              │
│  业务逻辑 + 你的数据（文本内容、状态变量）            │
└───────────────┬─────────────────────────────────────┘
                │  调用公共 API（ImGui::Begin/Button/…）
┌───────────────▼─────────────────────────────────────┐
│           Dear ImGui 核心（平台无关）                 │
│  imgui.h / imgui.cpp        —— 核心、窗口管理、输入    │
│  imgui_widgets.cpp          —— 各类控件实现           │
│  imgui_draw.cpp             —— 绘图、字体、纹理图集    │
│  imgui_tables.cpp           —— 表格                  │
│  imgui_demo.cpp             —— 演示窗口（学习宝库）    │
│  imgui_internal.h           —— 内部 API（进阶用）     │
└───────────────┬─────────────────────────────────────┘
                │  生成绘制命令列表 + 请求字体/输入
┌───────────────▼─────────────────────────────────────┐
│              后端 Backends（平台/渲染相关）            │
│  imgui_impl_win32.cpp/.h    —— 平台后端（窗口、鼠标键盘）│
│  imgui_impl_dx11.cpp/.h     —— 渲染后端（DirectX 11） │
└─────────────────────────────────────────────────────┘
```

### 1.2.1 核心文件（平台无关，你基本不用改）

| 文件 | 职责 |
|---|---|
| `imgui.h` | **公共 API 的唯一入口**。你写代码时只需要 `#include "imgui.h"`，所有 `ImGui::XXX` 函数都在这里声明。约 450KB，自带详尽注释。 |
| `imgui.cpp` | 核心逻辑：上下文管理、窗口系统、ID 栈、输入处理、样式、停靠（docking 分支）等。 |
| `imgui_widgets.cpp` | 各种控件的实现：按钮、文本框、滑块、下拉框、菜单、进度条…… |
| `imgui_draw.cpp` | 绘图底层：把控件生成的几何数据整理成绘制命令，管理字体纹理图集。 |
| `imgui_tables.cpp` | 表格功能（`BeginTable` 等），较新的模块。 |
| `imgui_demo.cpp` | **官方演示窗口** `ImGui::ShowDemoWindow()`，包含几乎所有控件的示例代码，是你最好的学习资料。 |
| `imgui_internal.h` | **内部 API**，包含 `DockBuilder` 等未公开的功能。进阶或做编辑器时才会 `#include` 它。 |
| `imconfig.h` | 用户的**编译期配置头**。默认全注释，用来开启 FreeType、自定义断言、调整默认数据类型等。 |

### 1.2.2 内嵌的第三方库（stb 系列）

`imstb_rectpack.h`、`imstb_textedit.h`、`imstb_truetype.h` 是 ImGui 内嵌的 **stb 单头文件库**，分别负责：矩形打包（字体图集布局）、文本编辑状态机（`InputText` 的光标/选区逻辑）、TrueType 字体光栅化（把 `.ttf` 转成像素）。它们以 `#define STB_XXX_IMPLEMENTATION` 的方式在 ImGui 内部被包含，**你不用碰它们**。

### 1.2.3 后端 Backends（平台相关，选一套接入）

后端分两类：

- **平台后端（platform backend）**：负责把操作系统的事件（鼠标、键盘、窗口消息）翻译给 ImGui。我们的平台是 Win32，所以用 `imgui_impl_win32.cpp/.h`。
- **渲染后端（renderer backend）**：负责把 ImGui 生成的绘制数据提交给某个图形 API。我们用 DirectX 11，所以是 `imgui_impl_dx11.cpp/.h`。

`backends/` 目录里还有 GLFW、SDL2/3、OpenGL2/3、Vulkan、DirectX 9/10/12、Metal、WebGPU 等几十套后端，你可以按需换。

> **关键认知**：核心与后端是**解耦**的。换一个渲染后端，你只需要换 backend 文件、改几行初始化代码，**业务代码一行不用动**。

## 1.3 渲染原理与工作流程

### 1.3.1 什么是"即时模式"（Immediate Mode）

传统 GUI（如 Qt、MFC、WinForms）是**保留模式（Retained Mode）**：

- 每个控件是一个**长期存活的对象**，存在一棵"控件树"里；
- 控件自己记住自己的状态（比如按钮是否按下）；
- 你通过**事件回调**（`onClicked()`）来响应交互；
- 框架负责在状态变化时决定"重画哪些区域"。

ImGui 是**即时模式（Immediate Mode）**：

- **没有控件对象，没有控件树**；
- 你的代码**每一帧**都从头到尾执行一遍，重新描述"界面长什么样"；
- `ImGui::Button("确定")` 这一行，既是"绘制一个按钮"，也是"询问按钮是否刚被点击"——**绘制与交互是同一行代码**；
- 画完这一帧，ImGui 内部就丢弃了所有控件的临时数据（**但不丢弃你的数据**）。

看一个对比：

```cpp
// 保留模式（伪代码，Qt 风格）
QPushButton btn("确定");
btn.onClicked = []{ do_something(); };   // 控件对象活着，靠回调
layout.add(btn);

// 即时模式（ImGui）
if (ImGui::Button("确定"))     // 这一帧画出来，同时返回"是否被点击"
    do_something();            // 点没点，当场就知道
```

### 1.3.2 每一帧发生了什么

ImGui 的一帧，就是下面这个循环（你在 `main.cpp` 里会反复见到）：

```
1. 处理操作系统消息（PeekMessage/DispatchMessage，转发给后端）
2. ImGui_ImplDX11_NewFrame();     // 渲染后端准备新帧
3. ImGui_ImplWin32_NewFrame();    // 平台后端准备新帧（刷新鼠标键盘状态）
4. ImGui::NewFrame();             // ImGui 核心开始新帧，清空上一帧的 UI 数据
5. ── 你的 UI 代码：ImGui::Begin(...); ImGui::Button(...); ... ──
6. ImGui::Render();               // 把这一帧所有控件"光栅化"成绘制命令
7. 拿 ImGui::GetDrawData() 提交给渲染后端 → 画到屏幕
8. Present（交换链呈现）
```

第 5 步是你的主战场。第 6 步是 ImGui 的"魔法"：它把你即时调用的这些 `Begin/Button/Text` 全部收集起来，**按层级排序、做裁剪、生成一批顶点缓冲和索引缓冲**，最终变成一个 `ImDrawData` 对象。

### 1.3.3 绘制命令与字体图集

ImGui 输出的不是一个"位图"，而是一批**绘制命令（draw commands）**。每个命令包含：

- 一组顶点（位置、UV 坐标、颜色）；
- 一组索引（三角形）；
- 一个纹理（通常是字体图集）；
- 一个裁剪矩形。

这些数据交给渲染后端后，后端用对应的图形 API（我们这里是 DX11 的顶点/索引缓冲 + 纹理采样）把它们画出来。

**字体图集（font atlas）**是其中唯一的纹理：ImGui 会把所有要用的字符（字形）预先光栅化到一张大纹理上，绘制文字时只是"从这张纹理里采样对应的字形"。这就是为什么：
- 加载字体要用 `io.Fonts->AddFontFromFileTTF(...)`；
- 中文字符集很大，默认字体不含中文，想显示中文必须加载一个包含中文的字体（见 02 章）。

## 1.4 与传统 GUI 框架的区别与优劣

| 维度 | 传统保留模式（Qt/MFC/WinForms） | Dear ImGui（即时模式） |
|---|---|---|
| 控件状态 | 存在控件对象里 | 存在**你自己的变量**里 |
| 事件处理 | 回调 / 信号槽 | 函数**返回值**当场判断 |
| UI 与逻辑 | 常常交织在控件树与回调里 | UI 代码直接写在你逻辑旁边，线性可读 |
| 布局 | 布局管理器，自动重排 | 手动：`SameLine`/坐标/大小，靠你自己算 |
| 复杂度 | 一套 UI 要建一堆类 | 几行代码就一个界面 |
| 性能 | 擅长复杂、稳定的应用 UI | 擅长工具/调试 UI、每帧都在变的界面 |
| 数据绑定 | 需要 MVVM 等机制 | 直接读写你的变量，天然"绑定" |

**ImGui 的优势：**

1. **极简**：写一个带按钮、滑块、文本框的窗口只要十几行，无框架仪式感。
2. **直白**：UI 代码就在业务逻辑旁边，没有"跳到回调函数里找逻辑"的心智负担。
3. **即时反馈**：改一行代码重新编译，立刻看到界面，迭代极快。
4. **平台无关**：核心代码一套，换后端即可跨平台。
5. **轻量**：无外部依赖，几 MB 源码直接编译进项目。

**ImGui 的劣势（要有清醒认识）：**

1. **每帧重建**：即使界面没变，每一帧你的 UI 代码都会重新执行（好在 ImGui 本身很快，且只有可见部分会生成绘制命令）。
2. **布局手动**：没有自动布局管理器，复杂响应式布局要自己算坐标。
3. **不擅长"数据密集型"控件**：比如几万行的表格、富文本、复杂主题系统，需要自己实现（这也正是我们写编辑器时要自己造轮子的原因）。
4. **不是"应用程序级"框架**：ImGui 定位是工具/调试 UI，用它做"消费级精美软件"需要额外投入。

> 一句话总结：**ImGui 适合"给你自己/同事/玩家用的工具界面"，传统框架适合"给最终用户用的产品界面"。** 游戏引擎编辑器、性能分析器、内部工具、调试面板——这些正是 ImGui 的主场。

## 1.5 坐标系与布局系统

### 1.5.1 坐标系

ImGui 的坐标是**屏幕像素坐标，原点在窗口左上角**：

```
(0,0) ──────────→ +X
  │
  │   窗口内容区
  │
  ▼
 +Y
```

- `ImGui::GetCursorPos()` 返回当前"光标"（下一个控件将被放置的位置）相对于**当前窗口**左上角的坐标。
- `ImGui::GetCursorScreenPos()` 返回相对于**整个屏幕**的坐标。
- 每个控件的宽度默认是"可用宽度"（窗口内容区宽度），高度由控件自身决定。

### 1.5.2 布局系统：基于"光标"的流式布局

ImGui 的布局核心是一个**光标（cursor）**概念：每次放置一个控件，光标就往下移动"一个控件的高度 + 间距"。下一个控件接着放在光标处。这就像打字时光标逐字右移一样自然。

```cpp
ImGui::Text("第一行");   // 光标往下走
ImGui::Button("A");      // 放在第一行下面
ImGui::Button("B");      // 放在 A 下面（竖着排）
ImGui::SameLine();       // 光标回到上一行，和 A 并排
ImGui::Button("C");      // 放在 A 右边
```

几个关键工具：

| 函数 | 作用 |
|---|---|
| `SameLine()` | 光标回到上一行，实现水平并排 |
| `Spacing()` | 空出一段垂直间距 |
| `Separator()` | 画一条水平分割线 |
| `Indent()/Unindent()` | 增加/减少缩进 |
| `SetCursorPos(pos)` | 直接把光标移动到指定位置 |
| `BeginChild()/EndChild()` | 创建一个独立的滚动子区域 |
| `BeginTable()/EndTable()` | 表格布局 |

### 1.5.3 窗口管理机制

ImGui 的"窗口"用 `Begin/End` 成对包裹：

```cpp
ImGui::Begin("我的窗口");   // 开始一个窗口（如果没创建就创建）
ImGui::Text("内容");
ImGui::End();               // 结束
```

窗口可以拖动、缩放、折叠、关闭，ImGui 自动处理标题栏和这些交互。窗口的状态（位置、大小、是否折叠）默认被**持久化**到 `imgui.ini` 文件里，程序下次启动会自动恢复——这是 ImGui 自动帮你做的，不用管。

**ID 系统**是窗口和控件的"身份证"。ImGui 用 ID 来区分"两个同名的按钮"、"同一个输入框的历史状态"。多数时候 ID 由名字自动生成，但当两个控件同名同位置时需要手动指定 `ImGui::PushID()` 或给名字加 `##` 后缀（详见 02 章）。

### 1.5.4 Docking（停靠布局，docking 分支特性）

普通 ImGui 窗口是浮动的独立窗口。**docking 分支**在此基础上增加了"停靠"：窗口可以拖到主窗口边缘或彼此吸附，形成类似 VS Code 的分栏布局。这对编辑器类软件至关重要。

核心 API：

```cpp
// 1. 开启 docking（在初始化时）
io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;

// 2. 每帧创建一个"停靠空间"，覆盖整个主窗口
ImGui::DockSpaceOverViewport(ImGui::GetMainViewport());
```

之后所有窗口都能被拖入这个停靠空间、自由分栏。进阶的"预设布局"用 `imgui_internal.h` 里的 `DockBuilder` 系列（我们在编辑器项目里会用到它来做一个默认的侧边栏 + 编辑区布局）。

## 1.6 本章小结与自测

你应当已经理解：

1. ImGui = **平台无关核心 + 后端**，核心不碰图形 API，后端负责接入具体平台和渲染器。
2. **即时模式**：没有控件对象，每帧重新描述 UI，数据存在你自己的变量里，交互靠函数返回值。
3. 一帧 = `NewFrame → 你的 UI 代码 → Render → 提交绘制`。
4. 坐标原点在窗口左上角，布局靠"光标"流式推进。
5. docking 分支提供了 `DockSpace` 停靠能力，是编辑器界面的基础。

**自测题：**

- 为什么 ImGui 的文本框内容必须存在你自己的 `char[]` 或 `std::string` 里，而不是"控件自己记住"？
- `ImGui::Button("x")` 返回 `true` 意味着什么？它在哪一帧返回 true？
- 想显示中文，为什么默认字体不行？

答不上来就回头重读对应小节。清楚了就进入[第二章：ImGui 基础使用](02-ImGui基础使用.md)，开始动手搭环境。
